# REVIEW_MODE.md

Use this mode when examining an already-developed project or codebase.

## OBJECTIVE

Understand before changing anything.

---

## REVIEW RULES

Do not rewrite first.
Do not refactor first.
Do not assume current code is wrong.
Do not assume current code is right.

First identify:

- architecture
- responsibilities
- dependencies
- code smells
- bugs
- risks
- unclear intent

---

## REVIEW OUTPUT

Report in these sections:

1. observed facts
2. likely issues
3. likely risks
4. unclear areas
5. recommended changes
6. changes that should not be made casually

---

## CHANGE SAFETY

Unless explicitly told to modify code, remain in analysis mode.
